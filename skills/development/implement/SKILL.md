> Skill Hub file reference: use this method under the target project's rules and task authorization; selecting or reading it runs no command or workflow. Linked methods are optional candidates, not automatic selections or archives; [maintenance notes](../../FILE-REFERENCES.md) are optional current-library guidance, and unprovided files or capabilities must be checked.

Implement the work described by the user in the spec or tickets.

Where useful, read [the TDD method](../../quality/tdd/SKILL.md) and work at the task's agreed test seams. Reuse decisions already made instead of requesting the same approval again.

Discover the project's actual checks. Run focused tests and typechecking while making changes, then the required checks at the end; report only commands actually run.

Once done, read [the review method](../../quality/code-review/SKILL.md) when a two-axis review is useful, and resolve material findings within scope.

Report the resulting changes, verification and remaining risks. Commit only when the task or established project rules authorize it, and only in the confirmed target worktree/branch; selecting this file does not itself authorize a commit.
