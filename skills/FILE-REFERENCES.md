# Skill Hub 文件引用约定

这里的技能是可编辑的方法文件，由当前标准 agent 按任务需要使用。Hub 发现目录、提供简述与版本化引用；选择、返回引用或读取文件均不证明已经执行或理解技能。Hub 不安装 slash 命令、不启动另一种 agent，不运行技能脚本，也不固定后续工作流。

1. 先用实际 `description` 判断相关性。正文中的相对链接和可选 `related` 只是可供继续判断的关联；不要自动选择全部依赖。引用相对其所在文件解析，确认目标存在后按需读取；不要把名字当作可调用的宿主命令。
2. 活跃文件可直接编辑。任务中的版本化引用指向选择时的归档；需要正文或附件时，使用 CLI 提供的归档读取入口。历史文件缺失、损坏或未归档时明确说明，不能用当前同名文件补造当时内容。共享的本文件若未包含在历史档案中，也不能假定它是当时规则。
   当前 ID 来自类别/方法目录路径；重分类或改名后，用刷新后的实际目录重新筛选，不继续提交旧 ID。已有方案及历史保留旧 ID 和字节，不把目录迁移解释为历史文件也已改变。
3. 目标项目的 `AGENTS.md`、既有上下文模型、文档布局、用户指示和已给授权优先。正文中的 `CONTEXT.md`、ADR、`.scratch/` 等是适用时的示例约定；不要为了技能创建另一套权威知识或修改无关项目。先确认项目、分支/worktree 和任务范围。
4. 提交、合并、分支/worktree 操作、删除原型、tracker 评论/标签/关闭事项、外部发布和消息发送都不是读取本文件自动获得的授权。任务已授权的操作可继续；未授权时先准备可审阅的结果，再按项目规则处理。保留真实的失败和未知状态。
5. 并行 agent 是可选实现方式，取决于宿主工具和任务授权。可用时给出独立任务范围，并按目标项目要求隔离写入；不可用时由当前 agent 分别完成各视角，不声称运行过子 agent。会话、上下文清理、模型/provider 和终端展示也不由技能假定控制。
6. 工具、浏览器、网络、tracker 和 Bash 都按实际可用能力核实；可使用既有连接器或项目工具。模板里的命令是供核对的示例，不是可直接执行的保证。没有外部 tracker 时，在已有项目任务文件中草拟；无须先配置一个服务。只在任务需要且授权时运行适用脚本，并记录实际结果。

维护技能时保留方法的适用条件、完成标准和必要附件，修改或删除时检查入链；Hub 的刷新只重建派生目录，不自动修复或改写正文。方法的来源许可见 [LICENSE](LICENSE)，适配记录见 [README](README.md)。
