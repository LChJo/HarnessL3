# Web投影与最终设计接入

规格v1.0，实现和平台验证见[实施状态](../implementation/STATUS.md)。视觉与交互只采用[已确认v0.16](../prototype/DESIGN.md)，正式数据来自[CLI公共用例](cli-contract.md)及[归档](storage.md)。

## 展示职责

首版Web是本机只读观测与原有检索操作的界面。项目/worktree选择器选择服务目标，不修改Git检出。主页保持状态总览，技术说明/原文/诊断放入详情；不增加架构介绍落地页、旧界面入口或第二套知识编辑器。

输入、五类上下文、上下文输出、下方Skill Hub与技能方案全部共享同一世界坐标与手势。首屏不展开子层；用户展开状态与相机是视图状态，不写入LikeC4、不变成模型任务路径，也不计读取。自动布局是可重建派生结果，历史任务保留当时组织所需数据，布局算法升级不能替换历史内容。

## 读模型

Web从同一核心用例获得当前项目/工作区、模型诊断、来源新鲜度、任务/批次、轻目录、实际返回包、技能选择/文件引用、采集覆盖及可用C4。公共持久记录为输入；客户端五类树、连线、聚合数、动画与可见前沿均为派生展示。

| 区域 | 实际依据 | 不可推断 |
| --- | --- | --- |
| 输入 | task目的、绑定目标、声明会话与请求来源 | 完整系统提示或完整聊天 |
| 对象 | 批次实际披露/返回对象及原祖先定位 | 父层或端点正文已读 |
| 关系 | 返回对象的直接关系/独立观测引用，保留来源/推断状态 | 连线等于执行先后或因果 |
| 来源 | 返回内容的来源声明与引用关联 | 声明即事实证实 |
| 证据 | 实际返回的证据引用、明确请求后返回的片段范围 | 引用已返回等于整个源码文件已读 |
| 版本 | 模型、来源指纹、扫描策略、worktree、核验范围 | 分支/commit即全部源码已同步 |
| 输出 | 累计实际上下文包、版本化文件引用和错误范围 | 模型已理解、最终回答或代码产物 |
| Skill Hub | 当时选择、理由、group、文件清单/指纹与独立读取回执 | 已选择或文件返回等于技能已执行 |

现有原型不保存完整业务源码副本。正式v1同样只自动归档上下文/技能与引用；历史中打开当前源码须明确“预览当前源码”，不能以当前片段冒充当时读取。日志只记录有依据的路径/范围/结果，不反向填入未知的正文哈希。

## 状态与连线

- 初始五类为定位入口。已披露简述、待获取候选、请求中、实际返回、引用、关联版本、错误与未知分别表示；实际返回可以同时点亮多个类别。
- 折叠父层聚合已知命中；分类计数不可简单求和为独立正文数。关系端点或来源边界只是定位，不能额外点亮为正文返回。
- CLI选择与网页手动选择保留来源；预设示例明确标为示例，不能冒充agent自主选择。
- Skill Hub默认闭合；打开只见实际文件夹，点击见skill，再点见文件引用；选前目录未选、选后只组织本次集合，文件夹显示所选数量。旧group优先归档，缺字段按原ID定位或明确未知。
- 选中到返回的动画只由真实批次/事件驱动，独立目标不为动效串行。事件到达不自动展开、不强制跟随相机；减少动态效果设置受尊重。
- 错误、采集缺口、最近有效模型、旧任务、部分恢复均有文字标签。Slate色板复用，不用颜色代替事实状态。

## 当前与历史隔离

服务为每worktree发布带单调提交序号的事件；Web按明确目标订阅。事件只提示有新提交，客户端重新取对应已提交状态，不把来自另一目标的ID拼接到当前树。重连按序号补取，缺口则拉完整快照；不能因为重复事件重复增加命中数。

打开历史时固定task及可选batch，使用当时归档。实时SSE可以提示有更新，但不改写已打开的组织；“最终组织”是显式新查询。模型无效、目录变动或另一任务的活动均不覆盖历史。查看/平移/展开/复制不更新最后读取活动。

## C4与本机边界

C4按需加载LikeC4当前有效视图，或历史归档中的当时视图。它呈现静态组成/关系，不负责检索顺序；技能不变成C4对象。旧历史缺图时显示未知，可显式选择“当前结构（非历史图）”，不能静默代替。

正式包提供本地Web资源，默认不依赖外部字体/CDN或外部API。用系统字体或许可清楚的随包资源保留原型的可读性与Slate视觉。布局/相机/展开状态可在本机视图配置中保存，但不是任务事实或权威文本。

服务鉴别与同源规则见[运行架构](architecture.md)。此产品不使用Codux notes/终端summary保存任务，开发里程碑与产品历史分别维护。

验收包含：三平台浏览器、手机触摸、点击锚点、层级隐藏、并发点亮、目录自动变更、双日志未知范围、历史SSE隔离、归档C4及离线资源。具体场景编号见[验收矩阵](acceptance.md)。
