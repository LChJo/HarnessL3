# 产品规格

v0.44（D05/D06/D14/D15）：FR01–03/07/09/12/15同样适用于普通目录，初始化、任务、上下文、技能、同步、历史和Web无需Git。已有Git目标仍要求可用Git；Git仓库创建由用户外部工具完成。普通目录初始化写入可编辑默认排除并读取多层.gitignore；原地启用Git保留项目/工作区UUID与历史，当前来源重新待核验，旧绑定通过历史恢复。目录未启用Git时提示随项目备份模型/配置/证据/文档/实际项目技能。

v0.43细化FR02/09/12/15的初始化恢复：安装入口可发现真实Schema与建模示例；嵌套来源边界准确表达且不自动排除；同步冲突指出具体变化、保留严格代次与历史，调用失败停止依赖成功data的后续步骤。原有文本权威、当前agent建模及显式来源范围不变。

v0.42细化FR15：首次接入必须实际调用当前宿主/模式可用且允许的原生询问工具，一次一问、给出必要选项并等待回答；异步返回或默认选项不代表同意。沿用既有授权/拒绝回退，不由CLI创建弹窗或等待终端输入。

v0.41细化FR07/09/14：项目切换主要服务观察复盘，默认恢复最近真实任务；当前状态读取不触发来源全扫。编码变化按路径增量观测且立即待核验，完整来源版本与增量观测范围分别表达；严格任务绑定和阶段核验不以缓存替代。性能同时记录可见耗时、扫描次数、实际读取文件及历史投影规模。

## 用户与结果

主要用户是正在受管理普通目录或Git worktree中工作的agent，以及查看其上下文组织的人。开发者提供任务目的，现有agent利用稳定简述，成批选择需要的项目知识与工作方法；CLI返回可追溯的上下文和技能文件引用。agent随后使用原有工具正常工作，并在阶段结束前核对源码变化与模型。

基准D15确认全任务/1%先尝试L3，每轮重判并读取所选技能正文，项目上下文独立复用；无适用技能显式空选。首次未登记由agent实际调用可用且获当前模式允许的原生询问工具确认，同意后机械接入及当前大模型建模，拒绝/取消本任务普通执行且不重问，已有授权复用。0.25将可视化提示改为实际上下文返回且必要技能正文读取后显示，仅使用格式化链接；初始化进度与语义覆盖由当前大模型如实报告。宿主遵守文件型skill，不增加Hook/agent启动；引导恢复不递归。

成功结果是：目标工作区明确，所选数据能快速定位和重复利用，Web可解释输入到上下文包的真实组织，60天内能够恢复当时的批次与文件。模型调用次数不由图的层级决定；不把“响应生成”描述为“模型理解”。

## 首版边界

| 首版包含 | 首版边界 |
| --- | --- |
| 多项目、普通目录和已有worktree登记、明确选择与恢复 | 不创建、切换或删除Git worktree/分支 |
| agent直接读写LikeC4、说明、证据与普通技能文件 | 不强制Model API/MCP或对象CRUD，不提供图形写回 |
| 混合批量披露、跨层正文读取、独立请求并发 | 不为每个节点调模型，不替现有agent做规则化技能选择 |
| CLI自动启动/复用本机服务、按需Web | 不启动agent、不选择模型提供方、不管理API密钥 |
| Codex和Claude Code的限定版本日志观测 | 不安装Hooks、不注入工具、不扫描无关会话，不承诺全量覆盖 |
| 文件历史、派生索引和只清派生的GC | 超期退出默认查询，首版不提供历史永久删除 |

## 标准工作流程

初始化分成机械接入与语义建模：CLI的init只保留确定性的缺失文件建立、身份登记、技能库首建和模型校验；返回scaffold-ready、实际对象/关系/视图数量及交给当前agent的后续动作，语义状态为not-assessed。当前大模型使用已有文件工具读取项目说明、目录及关键入口，直接编写或增量补全LikeC4层次、真实依赖和来源证据，报告阅读→建模→校验进度。覆盖范围由实际阅读与检查支持；机械成功、目录列表或单个边界模板不算项目结构建模完成。无需另起模型、额外API或脚本推断业务语义；CLI的解析、存储和索引等确定性基础设施保留。

实际上下文与必要skill正文返回当前agent后，取得真实链接，在进度消息中展示一次Markdown引用卡片，再继续用户工作。保留加粗标题“HarnessL3 · 本次输出”、空白引用行及“↗ 查看HarnessL3的输出”文字超链，不包代码围栏、不附裸网址、使用/选择说明或常规到期文案。卡片不表示用户工作已完成，空选择也遵守同一时机，最终答复不重复。默认后台为当前用户、默认数据根的一份常驻服务，无空闲超时；网页一次登录码/已登录会话与进程生命周期独立。

1. 已有普通目录或Git仓库/worktree由外部工具准备。首次窗口确认后机械接入，当前大模型阅读真实来源并直接补全模型、关系、证据及视图，报告进度/校验/覆盖后恢复任务；拒绝/取消普通执行。已有模型保留身份，旧历史不回写。
2. 当前agent每轮先判断操作所需技能及项目上下文可复用范围；按所需请求处理缺失安装及项目初始化/登记并复用授权，归档恢复不要求重新初始化；需要新入口时调用task start，提供目的、工作区及可选调用方会话声明，取得上下文筛选提示、顶层简述、Skill Hub原则和实际技能轻目录。
   按实际目标建档；每轮依据当前操作判断技能并返回所选正文，执行上轮待办/规划转实现不能跳过技能路由。同目标/版本合适且技能集合相同时复用原选择并task read；技能集合或所需版本变化时新建阶段任务，一次选择本轮技能及缺失项目上下文。项目正文可在agent对话中复用，新任务不继承旧packet，不跨任务使用known。材料丢失才handoff恢复，缺新内容才差量读取。无适用技能保持明确空选，不发空文件读取。不因计划、待办、技能切换或一轮回复结束自动关闭未完成任务，完成/取消实际范围并记录同步状态后关闭。subagent继承父选择并在受托范围内逐轮读取必要技能，不能重选或关闭父任务；不同技能需要授权的独立范围。父子/阶段关系是工作交接说明，不新增CLI字段、权限隔离或自动日志绑定。
3. agent一次提交所选目录/正文目标及含理由的技能集合。必要时先成批披露更多简述；已知目标可跨层直达，不必逐层点击或逐节点调用。
4. CLI核对目标、模型、源码及技能目录版本，归档实际返回内容。交接先返回上下文包与版本化技能引用；正文/附件按需读取。技能关联只是候选，不自动加入集合。
   实际上下文返回且必要skill正文读取后，agent用web open --no-open取得真实任务链接，按运行时skill在进度消息中展示一次“查看HarnessL3的输出”引用卡片，再继续用户工作；空选也遵守同一时机。卡片内容由agent输出，显示和点击效果取决于宿主TUI，不增加CLI渲染器。Web失败不阻断CLI。
5. Web按已记录请求、披露与返回投影命中；加载任务或目录更新不自动展开。浏览层级与agent读取分别计量。
6. agent使用普通文件工具继续工作。只读日志适配器记录能识别的真实工具操作；源码变化立即标待核验，未采集操作保持未知。
7. 源码、文档或知识阶段结束前，agent更新受影响的模型/证据/当前文档入链，或提交无语义变化核验依据；文档移动保留稳定身份并修复路径，删除/替代清理当前引用，历史保留。CLI保留证据异常并检查实际proof范围，无关局部核验可保存，未解决部分仍待核验。Git归属提示不要求先暂存；上下文任务关闭只记录本组织阶段的状态，不证明agent整体执行成功。
8. 历史查询恢复当时的输入、各批次、五类组织、技能方案和上下文包；查看不续期。

## 状态表达

FR12的错误读取要求调用方先判定`ok`，保留CLI退出码和完整错误，stdout/stderr分开；参数校验定位字段、说明约束并给出适用的修正指引。`known`提示明确默认空对象及同任务正文缓存含义，保留严格契约与未知写结果边界，不改已归档回执。

FR12同时要求区分初始化活锁与真正停止、控制端点运行与档案恢复进度；安装验证报告构建来源/运行指纹和实际服务/RPC，适用时对照更新前交接，不把静态帮助或未请求的历史检查当作恢复成功。服务控制端点在路径隔离预检后可用，目标请求仍等待对应档案与用例的完整验证；恢复失败保留degraded和实际范围。

用户可见页面和提示只呈现任务数据、操作及必要状态，不显示开发注释、实现解释或教学标语；工程说明不嵌入交付界面。领域简述、选择理由与实际来源/范围数据仍为产品内容。
明显损坏的选择理由给疑似编码损坏提示并允许查看原文，不猜写历史；中文请求优先明确的UTF-8文件以避免宿主管道输入前丢字，CLI只处理实际收到的字节。
模型有效性、源码新鲜度、采集覆盖、上下文请求/返回、技能选择/文件返回各自独立。合法模型可以待核验；观察到写入不代表知识已经同步；选择技能不代表执行；父层命中只聚合已知后代，不代表整个模块已读。

输入是本任务目的与实际请求，输出是交给agent的上下文包及引用，均不等于完整聊天或模型最终回答。未记录的工具活动不能用文件变化、静态关系或相邻时间补成执行路径。

验收映射见[验收矩阵](acceptance.md)。交互细节只在[最终原型设计](../prototype/DESIGN.md)维护，公共数据契约见[CLI规格](cli-contract.md)。
