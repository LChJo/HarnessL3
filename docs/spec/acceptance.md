# 正式CLI验收矩阵

v0.34的TC19逐一单独捕获21项默认方法，核对本地Markdown链接都能从该方法的归档清单读取，不含跨技能related；用户自有related候选仍按原契约处理。TC22用UTF-8文件（含BOM、中文路径）和UTF-8字节stdin传递中文/多语言/emoji理由，重启后原样恢复。TC21实跑桌面/手机详情与技能节点，疑似乱码提示可展开原文，正常提问和`??`/`?.`保持原样，方案/批次及旧归档不改写；不将输入前丢失的问号猜写成文字。

规格v1.0；下表定义完整验收目标，各子范围/平台的实际执行状态见[实施状态](../implementation/STATUS.md)。未有证据的范围继续planned。原型报告仅作设计和复用依据，不能将45项程序或34项界面历史检查填入此表作为正式产品通过。

v0.32恢复上下文返回后的发送时机，覆盖v0.31的最终答复末尾约束：实际上下文和必要技能正文返回后，取得真实task/worktree链接，在进度消息中展示一次卡片，再继续用户工作；取得上下文前不展示，后续查询/技能读取/最终答复不重复。保留v0.31的加粗标题、空白引用行及“↗ 查看HarnessL3的输出”链接，不包代码围栏、不暴露裸网址，窄终端自然换行；真实TUI的Markdown及点击效果按实际宿主单独记录。显式空选择、问答和开发任务使用同一时机，卡片不表示用户工作已完成。不新增TUI渲染器、Hook或agent启动行为。

v0.26的TC21同时核对正式界面文案：主页与技能/结构/历史详情不含固定开发注释、实现解释或教学标语；任务内容、必要状态、实际范围及明确打开的原文/诊断保留。此项以浏览流程和视觉检查留证，不以逐句文本匹配替代交互验收。

v0.28的TC20/21增加命中可见前沿：含大量未命中兄弟的层只显示命中/祖先及一个“…”；技能Hub层与文件夹成员一致，显式空选、未选择、历史目录缺失分别保真。点击后独立列表搜索/筛选/分页，DOM不随全部目录一次展开，刷新/前进/后退及返回相机有效；可显式选择正文/目录/技能，未选技能不能预览未归档正文。目录变更只更新相应当前列表，不覆盖历史；纯浏览不增加批次、读取活动或选择。以隔离大目录投影及真实浏览流程留证，合成渲染负载不冒充真实大仓库性能或数值SLA。

v0.29的TC21增加直接返回父对象自身正文：全部子对象未命中或父子同时命中时，自身正文叶子及绿色输出路径可见，分类计数不重复，点击打开原实体正文；仅祖先聚合不伪造自身命中，收起后路径仍保留。TC23增加重复打开原始登录链接、有效cookie不轮换/续期、新码仍消费、匿名/伪造cookie不能重用已消费码、跨源仍拒绝。浏览器实际验证401为登录恢复状态、地址栏去码且保留目标、新链接恢复及纯浏览前后任务记录不变；不将服务存活与凭证期限混称。

v0.30的TC21检查任务输入卡片/历史栏没有新建入口，空白工作区没有任务创建表单，标题/任务下拉/历史列表不附加“已关闭”；关闭任务仍按原规则只读。既有网页联合选择、幂等重试和显式空选通过CLI预建的隔离任务验收，不再以网页创建作为前置步骤。

## 测试夹具与隔离

Node内置测试用于核心、契约和子进程；Playwright用于Web。每次集成使用独立数据根、临时仓库/已有worktree、日志副本和可控时钟，不与正在运行的MGRP原型共享端口/registry/任务。真实宿主日志先脱敏取得固定样本，不复制整个用户会话；合成负例标注为合成。

三平台分别原生运行M1/M2/M3涉及文件系统和进程的场景。Windows Edge的原型通过不能替代macOS/Linux；Web CI使用可安装的Playwright Chromium，手机手势测试使用触摸仿真，实际设备兼容另标范围。

## 性能测量

v0.36的TC22/23增加：活启动锁且无描述时status为unavailable/startup-in-progress，stop返回BUSY并保留锁和所有者；并发调用等待既有启动过程，不额外spawn或依赖PID认证。故意阻塞档案恢复时控制就绪、健康和普通RPC仍可用，恢复进度真实且GC apply返回BUSY；目标历史仍完整验证，关闭不遗留恢复任务，构建诊断不透传未知属性。TC26增加包内构建来源/运行指纹、中文链接目录下真实执行验证工具、运行服务构建/RPC与旧handoff比较，以及改动对照包后的失败阶段；未提供对照保持not-requested，不把包安装成功扩称历史恢复成功。TC17同时记录从启动到首次交接的总耗时，区分真正减少恢复工作与移动等待位置。

固定MGRP规模基线（40对象/32关系/5视图）与生成的100、1000、10000对象分层数据集；生成器记录关系/证据/技能/历史数量与随机种子。单worktree及两个并行worktree分别测试，冷热缓存分开。

每个场景记录实际Node/LikeC4版本、OS、CPU、内存、磁盘类型、输入规模、样本次数、P50/P95、峰值RSS和磁盘占用；报告原始样本及失败率。测量涵盖索引损坏重建和日志积压，不能仅测热缓存。先完成可复现基线，再依据实测单独确认数值预算；本规格没有凭空设置SLA或宣称任何算法最优。

## 门禁与证据

每个里程碑先写能失败的行为测试再实现，保留命令、失败断言、通过结果和环境。Schema示例校验只证明契约自洽，不算正式功能RED/GREEN。场景状态只可根据本轮实际执行记录从planned改为passed/failed/blocked，注明范围及证据。

文档准备完成的检查是：链接与锚点、JSON Schema/示例、需求覆盖、状态与原型隔离、GC保留指纹及只读冒烟。这些不触发正式产品验收状态变化。既有缓存重试偶发问题见[实施问题V-P01](implementation.md#已知问题与实施期验证)。
