## SA01：正文完整交付

调用者拿到完整路由及所需方法正文，成功、失败、partial及正文缺失有明确区别；大响应可以用契约支持的精简/恢复方式处理。

- [ ] 保留 CLI 退出码、分开的 stdout/stderr 和原封套，判定 ok 后使用正文。
- [ ] 用长方法及较大目录验证实际交给模型的内容，包含方法尾部的必要指令；任意字符截断不能算完整返回。
- [ ] 目录、引用、文件落盘、元数据或哈希不能代替正文已经进入当前上下文的事实。
- [ ] 精简响应可按原任务/批次恢复匹配内容；失败或缺失保持可见，不自动换成当前版本。

## SA02：按所选方法工作

当前 agent 在用户授权和项目规则内，把完整返回的方法用于当前阶段，形成需要执行的动作、等待条件与完成条件；适用正文跨轮复用。

- [ ] 明确读取后的采用步骤，保留“读取不授予额外权限”的边界。
- [ ] 显式指定且目录中存在的方法按真实 ID/名称选择；名称或版本不匹配时如实说明，避免用项目材料中的相似名字冒充所选方法。
- [ ] 以访谈为例，实际工具调用、问题依赖、建议取舍、等待答案及下一轮更新可核对。
- [ ] 多技能、规则冲突、宿主缺少必要工具及阶段变化分别处理，不因新消息盲目遗忘方法或重新读全部材料。
- [ ] 文本核对、模型自报 adopted/applied 和实际行为分别报告。

## SA03：真实宿主行为验收

固定任务、方法版本和宿主/模型标签，在已授权的已知会话范围内对照无技能、现有交付、改进交付；去掉 deck 同名介绍等混杂信号。

- [ ] 基线在候选变更前采集；固定与任务相关、难以仅凭常识猜出的可观察要求。
- [ ] 区分选择、完整交付、逐项行为和任务结果；失败、未采集与未知分别保留。
- [ ] 多次新会话、跨轮、不同宿主/模型分别报告，记录真实工具调用及实际答案顺序。
- [ ] 不用原生 Skill 调用次数、技能名称出现次数或字节测试代替遵循率，也不从一条会话推出因果提升。
- [ ] 不扫描未知会话，不安装 Hook 或自动启动 agent；需要新增能力时另行明确范围。

## SA04：原版本恢复

发生宿主压缩、跨模型恢复或材料丢失时，当前阶段恢复其原任务/批次的方法正文，继续已获决策和授权。

- [ ] 恢复定位包含实际目标、task、batch、skill、文件和哈希，缺失才差量获取。
- [ ] 当前技能库变化不影响旧批次；同任务显式技能阶段仍可取得各自原字节。
- [ ] 在真实宿主复验压缩和跨模型恢复后所需动作仍可执行；丢失必须可识别，不能只凭“曾加载过”认定有效。
- [ ] 读取与浏览/技能读取的留存边界保持；版本丢失和损坏不借新版补造。

## SA05：原生适配候选

只在实际需要时验证通用原生入口：把明确已选的归档方法正文交给宿主原生 Skill 生命周期，而不复制整个目录为第二套注册表。

- [ ] 必须验证方法正文实际内联；入口只提示再调用 Bash 不算已完成原生加载。
- [ ] 明确目标/任务/批次/方法，检查失败、partial、长正文、多方法及参数转义。
- [ ] 实测当前宿主版本的压缩保留，和 SA03 基线对照；记录预算/丢失限制，不承诺强制遵循。
- [ ] 保留可编辑方法、独立归档、历史哈希与正常安装不覆盖用户库的边界。
