## 根因与边界

## 架构上补齐的部分

1. **语义建模与格式契约之间缺少安装端桥梁。** 模型由当前大模型维护、CLI 严格校验的边界保留；安装端现在能发现可执行校验的示例，避免依赖开发仓文档或凭 LikeC4 通用知识推测 HarnessL3 附加契约。
2. **来源边界与读取能力没有被错误模型准确区分。** 嵌套仓库原本就应阻止完整来源声明，但“特殊目录”诊断隐藏了真实边界。现在明确未知范围与可选恢复，不自动改变事实源。
3. **乐观并发错误缺少恢复所需的差异。** 不能靠重试消除旧 proof 的冲突；回执携带可追溯差异，区分代次、版本、两次采集和提交前变化。
4. **失败分支与消费方组合缺少回归。** 单测校验正确不保证 agent 能从打包契约发现、失败响应、修正和重新审核走完整条链路。本轮加入文档示例、PowerShell 子进程、CLI 失败恢复、历史回放与真实安装包断言。

## 验证与限制

首批五项回归在实现前全部失败，实现后全部通过。扩展程序测试、真实安装包检查及模型/证据同步的最终数量见 [实施状态](STATUS.md)；不要把首批结果等同全部程序或三平台通过。

本轮未对运行中的 MLDesigner 宿主、真实模型请求或首次询问窗口做新的端到端验收，未改写原任务/回执或自动恢复其全部 pending。修复语法不重新生成既有实体身份；修复源码不等于已更新全局安装、替换常驻服务、提交或发布。
