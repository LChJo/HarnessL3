# 初始化建模与结构演进（2026-11-11）

依据基准v0.47，范围为D01/D04/D08/D09/D15、FR02/03/07/09/12/15与TC03/07/08/10/21/22/27。用户要求改善初始化结构质量、提供agent补充/修订/重建入口，并使新项目模型随实现逐步补齐。

## 发现与实现

四项目当前正式模型的只读对照表明：joi只有根与14个直属模块；AI Mana Front虽有更深对象，12个叶组件未被任何现有视图展开。相同布局引擎的结果差异主要来自模型粒度与视图编排，未取得历史完整输入，不能据此比较大模型能力。冻结MGRP原型不作为正式模型统计依据。

新增`model maintain [--mode supplement|revise|rebuild]`，默认supplement。`core/model-maintenance.ts`提供版本化当前agent建模指引与机械视图覆盖检查；`init`复用同一指引，`task`路由和`sync status.modelMaintenance`提示日常结构复核。命令返回guidance-ready/not-assessed，读当前模型和显式证据、不请求来源全扫或改写项目文件；来源观测注明last-observed，可未知或过时；无活动资源时为null，不为指引恢复任务档案或新建观测。结果Schema随包提供并由核心和响应契约校验。

补充模式填新实现/遗漏；修订模式调整既有职责/依赖；重建模式重新审核声明范围并重组当前模型与视图，仍由当前agent用已有文件工具完成。相同实体保留harness_id，新增实体才建UUID，项目/工作区身份、历史快照和旧图保留。非法模型仍可取得真实诊断和修复指引、topology/coverage为空；权限失败不被当作普通无效模型吞掉。

覆盖检查报告对象/关系/层级、各视图节点/边及未入任何视图的叶对象，根模板、扁平结构与单根视图仅提示审核，不能机械判断项目语义是否完整。总览及必要专题视图按真实职责组织，不强制节点数量、深度或将所有对象塞入一张图。新项目仅表示已有实现；模块、入口、依赖和职责演进在对应开发阶段反哺模型、证据及当前引用。无语义变化如实说明。阶段核验仍使用完整sync status/verify、严格epoch/CAS；不引入后台模型、Hook或源码CRUD。
