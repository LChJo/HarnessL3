# 渐进披露的上下文检索与无限画布

- 已确认目标以 [项目基准](baseline-history-v0.16.md) 的 D10–D13 为准。已有原型读取命令与字段见第 9、11 节；技能联合入口见第 12 节链接，正式分发、预算与 agent 事件协议继续待定。

- 最新确认：用户已选 B 脑图，输入输出与上下文通过连线整体成为无限画布，取代 v0.9 固定外壳。首屏仅五类，点击后才显示子层，实际任务包分类投影已接入；[四版设计稿](design/five-information-options/README.md) 留作历史评审。

## 1. 任务路径如何界定

任务是一次需要获取上下文的目的，例如“排查下载取消后仍继续传输”。一次任务可以有多次请求；每次请求可以同时包含多个层级、多个模块与多种读取意图。

画布上的路径是**本任务实际披露与返回的上下文范围及其来源层级**。系统根据目录展开、批量读取及结果记录自动投影出来，AI 不需要另写一份路径计划。

这里的输出是模型正文、相关约束与证据引用组成的上下文包。AI 最终给用户的回答、代码修改、验证任务属于后续工作，不应被强行塞进这条检索主轴。

v0.6 的接收任务、业务入口、执行门面、调度、网络、输出六站，曾写在固定数组中，以预设时长演示点亮；原代码现归档于 `docs/reference/canvas-v0.6/`。它验证了画布、手势与动画，没有验证 AI 自主选择、渐进披露或并发返回。这种固定串行结构不应成为真实 agent 的必经流程。

## 2. 数据逐层披露，选择可以成批完成

| 层次 | 给 AI 的内容 | 目的 |
| --- | --- | --- |
| 定位简述 | 稳定 ID、名称、简述、是否有子项；必要的边界提示 | 让现有 agent 自己筛选相关区域 |
| 子层简述 | 多个选中父节点的子项简述，保留层级与来源 | 继续缩小范围，不先加载所有正文 |
| 目标上下文 | 选定对象正文、相关约束/关系、最小祖先定位、来源/证据与版本 | 一次获得本任务需要的多个目标 |
| 详细依据 | 指定文档段落或源码片段 | 需要时追加，不自动加载整个项目 |

复用的是现有 agent 的简述筛选能力，不为每个节点另启动一个模型。CLI/本机读取层做确定性的定位、展开、读取、合并和记录，通常不需要再向一个“路径规划 AI”发请求。

现有 LikeC4 `description` 已提供简述基础。详细上下文可以由对象字段、选中关系、长期说明与证据引用构成；详细文档的正式存放/引用规范仍待确定。长期简述随权威文本维护，语义变化时更新，不在每次检索时重新生成一遍。

## 3. 按标注图举例

```text
任务输入
  └─ 顶层简述
       ├─ 任务执行的子层简述
       │    ├─ TaskManager 正文 ──────────────────┐
       │    ├─ TaskScheduler 正文 ────────────────┤
       │    └─ ResourceTransferCoordinator 正文 ─┤
       └─ 网络与平台后端正文（或继续披露子项）─────┤
                                                └─ 合并为一个上下文输出
```

这是分叉、选择和汇合的记录。读取 TaskManager、TaskScheduler、传输协调以及网络模块之间没有预设的执行先后；能独立读取的部分可以并发，展示不应为播放动效而强制排队。

**下列请求已由原型读取层支持；正式产品协议尚未定稿：**

```json
{"expand": ["mgrp.execution", "mgrp.network"]}
```

一次返回两组子层简述。AI 据此选择多个目标：

```json
{"read": ["mgrp.execution.task", "mgrp.execution.scheduler", "mgrp.execution.transfer", "mgrp.network"]}
```

一次返回四项上下文。也可在同一个请求中同时 `expand` 尚不明确的分支、`read` 已确定的对象。已知 ID 时直接取正文；小模型或简述量很少时，可以在预算内一次披露多层，减少往返。并不要求每层、每节点对应一次工具调用或一次新模型推理。

父节点正文和子树正文是不同范围。读取 `mgrp.network` 不默认等于读取七个后代；需要子树时应明确说明范围。目录可见、候选选中、请求中和成功返回同样不能混为一个状态。

## 4. 减少模型负担的具体措施

1. **先给有区分力的简述**：表达职责、适用问题、边界，避免“负责某模块相关功能”等空话。区分相近模块，并提示已知交叉入口。
2. **批量筛选/读取**：一份返回承载多个父节点目录或多个正文目标，无需逐个模块交互。
3. **允许跨层与混合**：层级负责导航，不成为强制关卡；已知对象可直达，已明确的正文和待探索目录可一起请求。
4. **复用稳定信息**：从 LikeC4 解析派生目录与片段，按 worktree/内容版本缓存；不维护第二套对象权威，不在每次读取时额外调用模型重写摘要。
5. **按需增量**：调用方明确声明仍保留的对象/版本时，可只返回新增或变化部分；会话压缩或丢失上下文后可重新完整获取，不能仅凭曾经返回过就永久省略。
6. **控制扩散**：关系先给必要边界引用，不自动读取全部依赖；支持简述/正文预算和名称/关键词定位，避免摘要未命中时把相关分支永久排除。

渐进披露不自动保证最少工具往返或最低 token。简述过长、层级过深、每层只取一项会增加负担；需要用批量、适度预取和直达机制平衡。后续测量检索覆盖、漏选后的补取次数、往返、实际 token、延迟与输出体积，不以动效或机制直接宣称最优。

## 5. 并发与记录边界

并发发生在没有数据依赖的多个分支/目标读取之间。下一轮选择依赖上一轮简述时，仍存在真实的信息先后；它不等于四个目标必须串行读取。

每个请求应绑定任务、会话、worktree、模型快照，包含批次 ID、目标 ID、读取意图和明确范围；每个目标独立记录结果。单项失败不伪造整批成功；重复目标合并，重试不重复统计。按完成情况显示点亮，异步完成顺序不推导出对象间的因果链。

直接文件工具入口继续存在。可选的批量读取能力是文本优先工作方式的补充，不强制改用 CRUD/MCP 编辑模型。仅约束本次返回，不限制会话已有内容或其他工具读取。未采集部分保持未知，返回不等于理解。

## 6. 当前主页上方结构（v0.10 已实现，v0.13 保留）

- 采用 B 脑图：输入、中间连续的上下文区域、输出及连线共享无限画布，整体平移缩放。结构连线不冒充执行调用关系。
- 首屏仅显示五类一级入口及聚合点亮，点击才显示下一层，再点击深入或收起；任务/CLI/SSE更新不自动展开，不默认铺开全部模块或命中叶子。展开保留点击位置，概览由用户主动触发。
- 业务模块属于分类内部的子层；五类各自呈现命中内容。同一批返回可投影到多个类别，不要求 agent 筛选五次或启动新模型。
- 同一批请求的多个节点同时或按实际完成时间点亮；用层级细线表达来源，用批次汇合表达一次上下文输出。
- 目录已披露、正文待返回、正文已返回使用不同标记；父级只显示子项聚合，不能冒充整个模块已读。
- 默认看本次命中范围，读取/批次详情按需打开；v0.11 提供 60 天检索和按批次恢复累计组织，不要求 AI 按固定流程行事，也不虚构完整工具执行回放。

## 9. 已实现的读取契约 v0.1（原型）

```powershell
npm run context -- start --title '排查下载取消后仍继续传输'
npm run context -- query <task-id> --expand mgrp.execution,mgrp.network
npm run context -- query <task-id> --read mgrp.execution.task,mgrp.execution.scheduler,mgrp.execution.transfer,mgrp.network
npm run context -- show <task-id>
```

CLI 依赖已启动的本机服务，默认返回便于 agent 阅读的文本；`--json` 返回结构化结果。`--expand` 与 `--read` 可混用，多个 ID 逗号分隔；`--revision` 可显式核对模型版本。`start` 自动返回顶层简述。`--session` 仅为调用方声明的会话标识，不是已验证的 agent 集成。命令和字段是原型契约，不代表正式产品分发/工作区管理方案已定稿。

| 内部 HTTP | 行为 |
| --- | --- |
| `GET /api/context/overview` | 五类画布所需的对象、关系、证据引用索引和版本；不加载旧布局/源码片段，不计为 agent 正文读取 |
| `POST /api/context/tasks` | 创建任务，绑定当前模型与工作区，返回顶层简述 |
| `GET /api/context/tasks` | 当前工作区最近 50 项本机任务，主页快捷列表 |
| `GET /api/context/history?query=&from=&to=&offset=0&limit=20` | 60 天窗口内的搜索/日期/分页，总数与保留边界；单页最多 100 项 |
| `GET /api/context/structure` | 按需返回同一 LikeC4 主模型的真实布局视图、版本与有效性，不计正文读取 |
| `GET /api/context/tasks/:id?batch=<id>` | 已记录批次与累计精确对象包，可截取至指定批次 |
| `GET /api/context/tasks/:id/snapshot?batch=<id>` | 当时不可变模型/C4 快照；旧记录仅部分恢复，缺失/损坏明确报错 |
| `POST /api/context/tasks/:id/query` | `{expand: [...], read: [...], known?: {id: hash}, expectedRevision?: hash}` |

每个目标 ID 去重；同一请求的目录和正文独立组装，支持多个请求并发合并。该实现主要从缓存解析快照组装内容，不宣称 CPU 并行或已完成大规模索引。未知对象作为单项错误返回，成功项保留。模型失效或版本不匹配拒绝新读取，旧结果保留。

“对象正文”目前明确指：LikeC4 对象说明、元数据、祖先标题、直接关系的边界引用，以及模型/来源版本和内容指纹；不会隐式读取子树、兄弟对象或整份源码。详细 Markdown 正文的安装与引用规范仍待确定，源码片段可以另外查看证据。推断来源和未核验状态保留在 JSON、CLI 文本及复制包中。

`known` 只有在本任务已有同指纹正文时才省略重复正文，首次读取不会被其他历史声明跳过。缓存随模型、来源版本和所引证据新鲜度失效。持久任务/批次位于忽略的工作区状态目录；重启遇到未完成请求标为未知，不补造成功。

记录的观测层级为读取层已生成响应，并非所有 agent 已接收/理解的证明。`client` 是调用方声明；每批记录网页/CLI/API 来源，同任务混合调用不会继承错误来源。预设示例使用真实读取但明确标为预设，测试任务在标题标明自动检查。

## 11. 已实现的 60 天历史与结构查看

历史入口保留输入目的、任务/worktree/模型绑定、调用方声明的会话与来源、批次意图与单项目标结果、实际简述/正文/关系/证据引用及累计输出包。它是读取层观测，不是全部聊天、源码副本或模型最终回答。

新任务及批次引用内容寻址的不可变快照，快照含当时对象层级、关系、所引证据状态、来源版本与真实 LikeC4 布局。同内容共用文件，快照不作为新的可编辑主模型。任务与快照按 worktree 存在忽略的本机目录；运行历史不能像派生索引一样从当前文本重建。

保留时钟从最后记录的读取活动起算 60 天，浏览不续期。`history` 支持 `--query/--from/--to/--offset/--limit`，`show <id> --batch <id>` 只恢复该批结束前的累计内容。网页历史只读，打开后不受新 SSE 结果影响，“最终组织”主动加载全部已记录结果。过期只退出默认查询，按 ID 仍可读、不可追加；当前未永久删除超期文件。

升级前缺快照的旧记录仅恢复实际保存的范围，明确标记未知与不完整；损坏归档报错，不借当前模型填补。旧记录缺 C4 时可明确切换到当前项目图；历史源码预览也明确是当前文件。

“项目结构”和对象/关系详情按需打开 C4 图，当前/当时模型分别标记；非法当前模型只能显示标明身份的最近有效图。C4 展示静态职责与关系，脑图展示本任务的上下文组织。两者共用 `.c4` 权威模型。无限画布为 React/SVG 自实现，既未使用 Codux 共享黑板，也未接入白板引擎；开发终端 summary 不承担产品存储。

正式日志适配、归档备份/迁移和超期永久清理仍待确定。60 天边界测试使用可控时钟，并未完成 60 天实时时长运行。

## 12. 与独立技能选择的关系

入口提示把本检索提示与内置 Skill Hub 原则、实际技能轻目录一并交给现有 agent，由它一次提交上下文与方法集合。上方仍从 LikeC4/实际包派生五类；v0.16 下方独立连线脑图按 Skill Hub→实际文件夹→skill 名称→文件引用逐层展开，文件夹聚合本次已选数量，历史保留当时分类，不产生五类命中或 C4 对象。技能正文/附件是可编辑文件；交接先返回版本化引用，按需批量读取。目录自动更新/手动刷新不改写正文或已选方案，不新增模型调用。

后续回到标准 agent 工作方式，可用现有文件工具或本读取层补取上下文。所选技能文件与理由随批次归档，未记录或未确认的执行保持未知。CLI 联合选择格式、文件维护与交接边界见 [技能路由与任务入口](skill-routing.md)，不在本文复制第二份协议。
