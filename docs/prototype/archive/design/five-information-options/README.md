## 四版共有的结构

```text
固定输入  │  中央一整块上下文画布                          │  固定输出
          │  首屏：对象 · 关系 · 来源 · 证据 · 版本         │
          │  点击某类 → 该类模块 → 继续点击 → 具体条目     │
```

中央平移、缩放、展开时输入输出位置不变。首屏只显示五类一级入口及其任务命中聚合；子层点击后才出现，可收起或返回。类别点亮只说明其内部有命中，不能据此声称整类内容都已读。

## 四种候选

| 版本 | 组织与展开 | 优点 | 取舍 |
| --- | --- | --- | --- |
| A 五区折叠板（历史入口已停用） | 五个分类区域，模块和条目在分类内逐层展开 | 五类状态可同时对照，结构稳定 | 展开多类时内容变长 |
| B 五根脑图（历史入口已停用） | 五个分类根入口，点击后向外长出模块与条目 | 能保留来源层级，接近脑图感受 | 多分支打开后画布占地更大 |
| C 嵌套空间块（历史入口已停用） | 分类包含模块，模块内部再露出具体条目 | 整体感强，容易辨认范围和包含 | 深层区域需要更细致的缩放设计 |
| D 逐层聚焦（历史入口已停用） | 首屏五入口，进入后只显示当前层，通过面包屑返回 | 画面始终干净，层级深时仍清楚 | 同时比较不同类别需要切换 |

设计师建议优先比较 A 的状态总览和 D 的极简程度；最终由用户选版，建议不等于已选。

## 五类怎样映射现有上下文

五类是同一上下文的信息侧面，作为分类视图展示；不建立五套权威知识，也不要求 agent 发起五轮筛选。同一次精确对象读取，可把实际返回的对象说明、直接关系、来源、证据引用及版本分别投影到五类中。

| 一级类 | 子层组织示例 | 可展示的任务命中 | 语义边界 |
| --- | --- | --- | --- |
| 对象 | 任务执行、网络等模块 → 对象 | TaskManager、TaskScheduler、传输协调、网络模块 | 选定对象正文返回不代表整个子树已读 |
| 关系 | 执行协作、跨模块依赖等分组 → 关系 | TaskManager 调用 TaskScheduler 等直接关系 | 必要边界引用不等于端点正文，推断保留未核验状态 |
| 来源 | 源码、人工维护、推断 → 关联模块/条目 | 返回内容的依据类型及所关联模块 | 来源声明不自动提升为已证实事实 |
| 证据 | 执行、网络等范围 → 引用/文件片段 | 已返回的证据引用、另行取回的源码片段 | 引用已返回与源码片段已读取分别记录 |
| 版本 | 模型、源码、工作区 → 关联版本状态 | 返回快照、对应源码与所引文件状态 | 分支/commit 不独立证明整个工作区语义同步 |

具体内部层级、跨类跳转、状态命名和数值由选版后继续细化。当前样例的命中仅用于比较设计，不代表已接入真实五类投影或完整 agent 轨迹。
