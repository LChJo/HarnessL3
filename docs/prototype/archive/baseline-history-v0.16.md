## 15. 技术依据

- [LikeC4 Model](https://likec4.dev/dsl/model/)：层级对象、关系、描述、链接及元数据。
- [LikeC4 Views](https://likec4.dev/dsl/views/)：同一模型的多个视角与粒度。
- [LikeC4 CLI](https://likec4.dev/tooling/cli/)：文本文件解析、校验、预览与热更新。
- [LikeC4 AI Tools](https://likec4.dev/tooling/ai-tools/)：可选 skills/MCP 能力，当前不作为 agent 文件编辑的前置条件。
- [Git worktree](https://git-scm.com/docs/git-worktree)：多个工作树、分支检出与共享 Git 数据的边界。

以上依据核验于 2026-11-04。实际实现需锁定依赖版本并验证对应能力。

## 18. 当前检索目标：批量渐进披露

输入任务后，agent 复用顶层简述筛选；可一次获取多个父节点的子层简述，再一次读取多个选定对象，或直接跳到已知对象。同一请求可以混合目录披露和正文读取；独立读取允许并发，真实数据依赖仍按需要先后发生。

路径由这些请求及其结果自动生成，AI 不承担额外的路径规划/解释任务。上下文输出保留精确目标、来源、必要约束与证据、版本和未核验状态；不自动带上整个父模块、所有兄弟或递归依赖。

2026-11-04 已只读验证快照可派生 11 项顶层简述，一批展开任务执行/网络两分支获得合计 11 项子简述，三个执行子项与网络模块组成一批 4 项上下文。该次选择为示例指定；2026-11-05 已进一步通过 CLI 实际执行该流程，记录见第 19 节。尚未验证检索选中率、实际 token 成本或延迟预算。

本轮以批量/跨层读取、混合意图、去重、部分失败、版本与来源保留为实现切片；详细契约和保留范围见 [渐进披露检索设计](context-home-design.md)。

## 19. v0.8 渐进披露读取切片（读取层继续复用）

- **读取层**：从有效 LikeC4 快照派生顶层/子层简述；一次请求可混合多个 `expand` 与 `read`，已知 ID 可跨层直达。对象正文仅包含选定对象说明、元数据、祖先定位、直接关系边界、来源/证据和版本，不隐式取整个子树或源码。
- **现有 agent 筛选**：新增可选 `npm run context -- start/query/show/list`，与网页使用相同本机读取服务。CLI 返回真实简述与上下文；不新增路径规划模型或逐模块模型调用，也不取代直接文件工具。
- **任务与批次**：任务绑定当前模型版本与模型/来源工作区身份，记录各批目标、意图、时间、单项结果和调用方声明的来源。支持多个请求合并、去重、部分失败；版本不匹配拒绝新读取而保留旧包。重启中的未完成请求保留未知。工作区身份目前为模型/来源路径派生标识，不是完整项目/worktree 注册管理。
- **缓存与持久化**：解析/正文缓存是可重建派生结果，按模型、来源版本和所引证据新鲜度失效。`known` 仅对本任务已保留的同指纹正文省略重复内容。任务/事件留在忽略的工作区状态目录，不进入 Git。
- **画布**：根主页只展示任务、顶层模块和上下文输出；多分支可同时展开，目录/正文可成批选择。视觉展开不冒充正文读取；候选、请求中、目录披露、正文返回和父级聚合分别表达。点亮由实际读取结果驱动，鼠标/双指平移缩放与按需证据继续可用；复制包保留推断及未核验标记。
- **观测边界**：当前记录为 `reader-response-produced`，不证明所有 agent 已接收/理解，也不是完整工具日志覆盖。网页手动、预设示例、CLI/API 与混合调用分别标明；预设只确定选择，执行真实读取。源码新鲜度仍限所引证据核对。
- **验证**：16 项程序测试、6 项真实 CLI/HTTP 检查、15 项独立 Edge 浏览器检查及 TypeScript/生产构建通过。覆盖混合/跨层、多分支、精确范围、并发合并、单项失败、版本/worktree 隔离、重启未知、缓存新鲜度、包与证据、SSE、重试、手势和实际返回动画；未执行完整 A01–A10。
- **实际使用**：当前协作 agent 已通过 CLI 读取 11 项顶层简述，一批展开任务执行/网络，再一批取回三个执行子项与网络模块。该样例未引入额外模型调用，不构成自动筛选准确率、token 节约率或性能 SLA。

## 20. 历史设计评审：v0.9 五类入口与固定外壳

本节保留当时的候选设计和核查。用户随后选择 B 脑图，并明确输入输出一起成为无限画布，取代本节的固定外壳；当前目标与实现以第 21 节为准。当时要求如下：

- 输入与输出固定显示，作为画布外壳；中央文档/上下文是一个连续的整体区域。拖动、缩放或展开仅作用于中央。

### 60 天查询与恢复

- 顶部“历史”可按任务目的、ID、声明会话或模型版本检索，并按最后活动日期筛选、分页查看；不受主页最近 50 项下拉列表的限制。CLI 新增 `history`，`show <id> --batch <batch-id>` 查看指定批次时的累计组织。
- 原型以最后一次已记录读取活动计 60 天，查看历史不续期；边界日仍在窗口内。过期任务退出默认检索，已知 ID 仍可只读查看，拒绝继续读取；本轮没有永久删除本机文件，清理与备份策略尚待确定。
- 保存范围是任务输入目的、调用方声明的会话/来源、worktree/模型版本、各批请求与时间、实际简述和精确正文、关联关系/来源/证据引用，以及据此组装的上下文包。输入不等于完整会话或系统提示，输出不等于模型最后回答；未采集工具操作继续未知。
- 新任务及批次保存内容寻址的不可变上下文快照，包含当时对象、关系、所引证据及其新鲜度、来源版本和 C4 布局；相同内容共用一份快照。历史快照是观测依据，不参与权威模型编辑，也不能以当前文本重新生成冒充当时记录。
- “记录→查看此时上下文”按批次恢复当时累计简述、五类点亮和输出包。历史模式只读，实时事件不会改写已打开的组织；“最终组织”主动读取该任务全部已记录结果。历史中的结构图标“当时模型”。
- 升级前没有完整快照的旧任务仅从实际保留的简述、正文、祖先定位和引用恢复，明确标记部分恢复、未记录区域未知，不借当前模型填充。旧历史没有 C4 图时可显式选择“查看当前项目结构（非历史图）”。归档缺失/损坏报错，不静默替换。
- 当前归档保留证据引用和版本，不保存全份源码副本；历史证据按钮明确为“预览当前源码”。新鲜度仍仅限所引文件的核对，不表示整个项目语义同步。
