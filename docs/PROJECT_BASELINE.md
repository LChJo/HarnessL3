## 1. 产品目标与首版范围

构建面向agent的项目上下文CLI：LikeC4文本表达对象、关系和项目知识，agent使用已有文件工具直接理解与维护。稳定简述用于一次筛选多个目录/正文目标，按需渐进披露和跨层直达，独立读取可并发，不为每个节点额外启动模型。

现有agent主动调用CLI，取得上下文筛选提示、内置Skill Hub路由原则和实际技能轻目录，一次批量选择上下文与技能。交接提供精确上下文及版本化文件引用，普通技能正文/附件按需读取，随后回到agent标准工作过程。CLI不启动agent、不选模型提供方、不管理API密钥、不执行技能。

首版支持多个项目及已有Git worktree的登记、定位、隔离与恢复，不创建/切换/删除worktree或分支。正式栈为Node.js+TypeScript/npm，Web沿用React/TypeScript/Vite；Windows、macOS、Linux都是验收目标。任务/事件/快照以文件归档，SQLite仅为每worktree派生索引。

Web以清爽的任务状态为主，输入、五类上下文、输出与下方Skill Hub共享连线无限画布。初始五类与闭合Hub，点击逐层展开；技能按实际文件夹→skill名称→文件引用展开。Slate视觉和v0.16交互冻结。C4按需呈现同一权威文本的静态结构，不作为检索顺序。

输入指任务目的与实际请求，输出指交给agent的上下文包，不等于完整聊天或模型最终回答。60天历史可按批次恢复当时组织。首批日志观测为Codex与Claude Code，只读既有日志、不装Hooks；未采集或无法识别的操作保持未知。

## 2. 已确认决策

| ID | 决策 | 必须保留的含义 |
| --- | --- | --- |
| D01 | LikeC4文本主模型 | .c4/.likec4是可编辑权威，对象/关系/视图由文本派生 |
| D02 | 现有文件工具优先 | 不强制Model API、MCP或对象CRUD作为编辑前置条件 |
| D03 | 五类信息与依据 | 区分对象、关系、来源、证据、版本；事实/人工/推断和核验范围可辨，不复制五套权威数据 |
| D04 | 三类编辑 | 视图、知识、源码修改分别保存/生效；图形变动不表示源码已变，源码变动需反哺模型 |
| D05 | 每分支独立worktree | 项目/分支/worktree分开，读写明确归属；不能切换其它并行任务检出或混用数据 |
| D06 | Git与本机持久化边界 | 权威模型、长期说明、证据引用随Git；索引/缓存/布局/运行记录按worktree本机隔离 |
| D07 | 查找与读写优先 | 接受空间换性能；SQLite/缓存可重建，不维护第二套对象真相；性能用测量说明 |
| D08 | 即时待核验、阶段同步 | 源码变化立即标pending，阶段结束前更新/校验或明确无语义变化；失败/并发新变动不伪报同步 |
| D09 | 真实读写轨迹 | 取受支持agent既有工具日志，未采集为未知；变更≠读取，读取≠理解，调用≠成功 |
| D10 | B脑图与统一无限画布 | 输入/五类/输出共享world，首屏五类、点击逐层、折叠聚合、事件不自动展开；不伪造固定执行路径 |
| D11 | 简述复用与批量披露 | 支持多分支、多目标、跨层和独立请求并发，不为绘图逐模块调用模型 |
| D12 | 60天当时组织 | 从最后实际上下文读取活动计期，无读取用创建时间；恰好60天仍可见，严格超过退出默认查询；浏览/技能读不续期，缺失不补造，首版不永久删除历史 |
| D13 | Skill Hub与文件引用 | 仅路由原则内置；普通技能可编辑、实际目录自动更新/刷新；一次联合选择、引用先行、正文按需；不自动加入依赖或执行；文件夹只聚合本次所选，历史保留原group/ID/字节 |
| D14 | 正式首版工程与接入边界 | Node.js+TypeScript/npm、三平台；现有agent主动调用；只登记已有worktree；文件归档+SQLite派生索引；Codex/Claude Code只读日志，不装Hooks、不启动agent |

## 3. 数据权威与维护

LikeC4模型是权威上下文，普通技能是独立文件来源；证据保存引用、主张与可核对版本，不以一份证据哈希证明全项目语义同步。稳定身份、别名/重命名与删除边界见[模型契约](spec/model-context.md)。正式代码采用项目.harness与机器数据根，不将原型机器路径当通用配置。

默认技能库首次发布完整持久实体，再以独占symlink（Windows junction）建立skills目录入口，避免POSIX rename覆盖并发出现的空用户目录。入口内文件仍可编辑；同级`.skills-library-<UUID>`实体属于用户技能库，不能作为临时文件或GC缓存删除。此为D13“不覆盖用户库”的实现细化，不新增技能权威。

agent直接维护模型和知识；Web首版不作图形编辑写回。视图表达可随文本版本化，自动布局/索引属于派生数据。源码变更需判断哪些对象、关系、说明和证据受影响；无语义变化时如实记录核验，不制造图变化。

机器运行记录、任务快照与技能归档不是可重建缓存，不能凭当前文件补造。取消登记不删除源码或历史。原型导入显式dry-run/复制/幂等，保留源；首版GC只清确定可重建/未提交临时产物，不能永久删除任何历史、用户技能或孤立档案。

源码新鲜度与模型有效性分开；同步proof绑定来源版本、扫描策略和代次。服务只做机械核对，语义结论保留调用方声明和依据，不能宣称自动理解。详细失败与并发处理见[观测/同步](spec/observation-sync.md)及[存储](spec/storage.md)。
