# Observation fixtures

`codex-synthetic.jsonl` and `claude-synthetic.jsonl` are fabricated protocol fixtures, not captured user conversations. `__WORKTREE__` is replaced with an isolated temporary directory by the tests. The secret markers verify that transcript text, commands, prompts, patches and tool output are never persisted in normalized observations.

Synthetic fixtures verify parser behavior only. They do not establish compatibility with an installed host version. Version validation requires the separately identified, minimally desensitized real transcript fixtures.

`codex-real-0.162.1.jsonl` was reduced from the explicitly authorized current-project Codex rollout. The real `custom_tool_call` / `custom_tool_call_output` envelopes, `input_text` result block type, AST control structure and numeric result metadata are retained. Session/record identifiers, timestamps, cwd, all paths, bodies and other string literals are replaced. Unsupported command literals become `unsupported-fixture-command`. This real wrapper has multiple children, so its successful aggregate is deliberately **not** evidence that each read succeeded. The independent single-read fixture below provides a separate real success case.

`codex-real-single-read-0.162.1.jsonl` additionally retains the shape of a real, explicitly paired standalone `Get-Content -LiteralPath` read performed by the root agent to check the project README. The wrapper has one awaited literal tool call and immediately publishes that result. Its actual exit code and numeric result metadata remain; filename, cwd, identifiers and all stdout are replaced. This proves the narrowly supported successful single-read shape, without treating aggregate execution as individual success.

`codex-real-failed-read-0.162.1.jsonl` retains one separately authorized, actual standalone read of a nonexistent fixture path. Its uniquely paired real result has `exit_code: 1` and no running session. The AST/control shape, result block types and numeric metadata remain; cwd, nonexistent filename, identifiers, timestamps and every original stdout/error string are replaced. This validates the narrow failed-read result, including `failed`/`nonzero` without claiming returned content. It does not establish cancellation or session-polling compatibility.

`codex-real-tool-boundaries-0.162.1.jsonl` retains five actual independent wrappers from the same explicitly authorized rollout, each performed on a root-generated synthetic file: a read that returned a running `session_id` without an exit code and with truncated output; a later nested `tools.write_stdin` sending Ctrl-C whose actual result was code 1; a `Get-Content -TotalCount 2` read returning code 0; `rg --files` returning code 0; and `rg -n` with no matches returning code 1. Original AST/control structure, literal command syntax, numbers, booleans and result block types remain. Paths, IDs, patterns and stdout are replaced; the process ID is consistently changed to a fixed fixture number and only the truncation marker is retained. Nonempty nested polling is unsupported, so its code 1 does not resolve the original read or prove a cancellation category. That event stays unknown/running. The limited read has requested lines 1–2 but no proven returned range. Both `rg` cases remain searches, and code 1 with no matches is successful search, not failed read.

`codex-real-empty-poll-0.162.1.jsonl` is a later, separately identified real read of the same synthetic source that was allowed to finish naturally. One literal read returns a running session, two independent empty-input polls remain running, and the third actual empty poll returns code 0 without a session. Every output is truncated. The exact single-result AST/control wrappers, envelope types and numeric metadata remain; session IDs are consistently replaced, all content/paths are removed, and only truncation markers remain. The adapter associates each poll within the original binding, retains one event, records the final zero exit category and keeps context status unknown/partial because earlier output was truncated. Body-free provenance is `.harness-local/implementation-20261105/observation-real-empty-poll-shapes.json`.

Code-mode polling is deliberately restricted to two statements (ignoring empty statements/comments): `const r = await tools.write_stdin(<one literal object>); text(r);`. The literal session must already belong to that binding; `chars` must be omitted or an empty literal string. Tests reject dynamic IDs/arguments, multiple polls, nonempty input, extra statements, a different printed variable, and IDs known only in another binding. Synthetic restart tests verify untruncated completion and that a later small successful frame cannot clear an earlier truncation flag. No logged JavaScript is executed.

`claude-real-2.1.212.jsonl` contains reduced tool pairs from the user's explicitly authorized Claude project directory, using only direct `.jsonl` files. The retained pairs cover Read (text), Edit, Grep, Write and the Bash transcript envelope. Numeric Read ranges and boolean result fields remain; body, patch, query, command description, stdout/stderr, original paths and identifiers are replaced. Bash's command is replaced by a deliberately unsupported compound fixture; it does not establish real literal-shell compatibility. No Glob record was found in that original corpus; the separate isolated fixture below supplies a narrow real Glob case.

`claude-real-tools-2.1.212.jsonl` comes from a separately authorized, root-generated real Claude Code 2.1.212 probe on synthetic files in its own temporary project. It is **not** extracted from the 268 user-project logs. It retains three actual pairs: a nonexistent-file Read with `is_error: true`, a Glob returning one filename with `truncated: false`, and a Read with `offset: 2` / `limit: 2` whose actual `startLine: 2` / `numLines: 2` establish returned lines 2–3. The host reported `totalLines: 5` (retained verbatim). Tool envelopes, names, input numbers, numeric metadata and booleans remain; all original identifiers, timestamps, paths, chat, descriptions and bodies are replaced. The test asserts failure versus success and exact requested/returned ranges, without inferring understanding, version or a current-file hash. The source log's byte hash was unchanged by extraction. Body-free provenance and shape evidence is retained locally in `.harness-local/implementation-20261105/claude-isolated-probe-shapes.json`.

`claude-real-interrupt-ambiguous-2.1.212.jsonl` comes from a separate authorized, root-generated synthetic Grep probe. The host acknowledged an official interrupt request, but the collected result contains only `is_error: true` and the generic static `toolUseResult` marker `User rejected tool use`. The fixture preserves that marker and the tool-result prefix while replacing all remaining content, paths, query and IDs. The adapter correctly records failed with an unknown exit category: this transcript cannot distinguish control interruption from ordinary rejection. External probe acknowledgement is provenance, not additional decoder input. The actual in-flight snapshot contained no tool call, so it is not described as a genuine missing-result transcript.

`claude-real-literal-bash-2.1.212.jsonl` is from a third separately authorized, root-generated synthetic project. Actual host calls were three independent literal commands: `cat sample.md`, `rg -n` with a literal pattern and filename, and `cat missing-fixture.md`. The first two result envelopes have `is_error: false` with structured `toolUseResult` and `interrupted: false`; the last has `is_error: true` with a string result. There is no numeric exit code to invent. Command syntax, booleans and envelope structure remain; pattern, descriptions, IDs, cwd and all stdout/stderr are replaced. This verifies successful read, successful search and failed read without generalizing to compound or dynamic Bash.

Two tests deliver a real Codex or Claude call first and append its original paired result later. These are explicitly controlled fixture prefixes of complete real pairs. They verify unknown/unmatched before the result and a single updated event afterward; they do not claim either host actually lost a supported tool result. Body-free shape/provenance evidence for the three additional fixtures is `.harness-local/implementation-20261105/observation-isolated-boundaries-shapes.json`. Extraction verified that the original source byte prefixes were unchanged, allowing the active Codex log to continue appending normally.

Extraction discarded all prompts, chat, thinking, base instructions, metadata passthrough, credentials and user business content. No user log or host configuration was modified. The temporary local extractor was removed after producing the fixtures.

Real-host boundary coverage now includes failed reads, Glob, limited reads, files-only/no-match searches, controlled missing-result delivery, code-mode empty polling through natural process completion, and actual interrupted probes with deliberately conservative unknown attribution. Top-level direct polling and an untruncated completed polling chain remain synthetic-only; a transcript marker that uniquely identifies cancellation is still unproven. This is narrow compatibility evidence, not complete host coverage. The earlier read-only audit of all 268 directly authorized Claude JSONL files found Read 31, Bash 132, Edit 22, Grep 14 and Write 3 matched calls, no Glob, no unpaired supported calls, no `is_error: true` and no `interrupted: true`. The Codex audit found nonzero child-result blocks inside aggregates, which are not proof of an individually failed read. All later failed-read and isolated fixtures above are separate from that audit. Body-free aggregate evidence is retained locally at `.harness-local/implementation-20261105/observation-real-shape-audit.json`. These counts describe only the explicitly authorized files, not all possible host behavior.

The subsequent explicitly authorized recursive audit stayed inside that same Claude project directory, traversed all four directories and skipped links/reparse points. It found the same 268 direct JSONL files and **zero nested JSONL files**, including a case-insensitive suffix check. The supported-tool pair counts and missing-result/error/interruption/Glob counters remained unchanged, so that recursive search supplied no additional real fixture. An all-tool counter also found 173 other, unsupported calls, 122 paired and 51 without a matched result; these are not substituted for supported Read/Grep/Glob missing-result coverage. Neither category contained a true error/interruption flag or cancellation marker. The body-free recursive evidence is `.harness-local/implementation-20261105/observation-real-recursive-shape-audit.json`; it does not extend the search to other projects or global session directories.
